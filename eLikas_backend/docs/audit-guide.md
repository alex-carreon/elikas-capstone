# Audit Logs — Developer Guide

Auditing in this project uses a custom implementation of the `owen-it\laravel-auditing` package. For more information on the project's use of the package, scroll down to the `Implementation` section. 


## Audit Log Endpoints

All log retrieval endpoints are currently only available for `admin` users and therefore require a correctly authorized firebase token. 


### `GET api/admin/audit-logs`

Returns a paginated list of audit logs with minimal data. All query parameters are optional — omitting one skips that filter entirely.

#### Query Parameters

**Search / String Match**

| Parameter | Type | Behavior | Example |
|---|---|---|---|
| `search` | string | Partial match anywhere in the user's first or name (if the relationship exists), the govOp's location name, or the logId fields | `?search=Pasa` |


**Filters**

| Parameter | Type | Behavior | Example |
|---|---|---|---|
| `user_id` | integer | Matches audit logs generated by a specific id | `?user_id=10` |
| `target_id` | integer | Matches logs from a specific target record id, recommended to use with `target_table_id` to return logs from a single record | 
| `target_table_id[]` | integer | Retrieves logs from a specific table using its id, recommended to use with `target_id` | `?target_table_id[]=4` |
| `user_type[]` | string | Matches logs from certain user types | `?user_type[]=brgy_op&?user_type[]=admin` |
| `event[]` | string | Returns all logs of a certain type | `?event[]=created` |


**Date Range Filters**

| Parameter | Type | Behavior | Example |
|---|---|---|---|
| `logged_before` | `YYYY-MM-DD` | Audit logs generated on or before this date | `?logged_before=2025-01-01` |
| `logged_after` | `YYYY-MM-DD` | Audit logs generated on or after this date | `?logged_after=2024-06-01` |

Both can be combined to express a range. Invalid date strings are silently ignored.


**Sorting**

| Parameter | Type | Default | Example |
|---|---|---|---|
| `sort_order` | `asc` or `desc` | `desc` | `?sort_order=asc` |

By default, the latest logs are returned first in descending order.


**Pagination**

| Parameter | Default | Description |
|---|---|---|
| `page` | `1` | Page number |
| `per_page` | `15` | Results per page (Laravel default) |

Only parameters in the explicit allowlist are processed. Any unknown query parameters are stripped before reaching the filter layer.


#### Example Requests

```
# Search for "Ibanez"
GET /api/admin/audit-logs?search=Ibanez

# Search for partial/complete log ID
GET /api/admin/audit-logs?search=U5B7

# Sensor-related audit logs 
GET /api/admin/audit-logs?target_table_id[]=4

# Complete audit history for sensor ID 23
GET /api/admin/audit-logs?target_table_id[]=4&target_id=23

# Audit logs created by user ID 10
GET /api/admin/audit-logs?user_id=10

# Delete-related audit logs by admins
GET /api/admin/audit-logs?event[]=deleted&user_type[]=brgy_op

# Find Audit logs between dates
GET /api/admin/audit-logs?logged_before=2025-01-01&logged_after=2024-06-01
```

### `GET /audit-logs/{id}`

Shows the complete details of an audit log, including additional information such as json `new` and `oldValues`, `ipAddress`, and `userAgent`.


#### Response Format

```json
{
    "data": {
        "id": 5,
        "logId": "U5B7716",
        "userType": "brgy_op",
        "userName": "Admin Hazelle Ann Gamoras",
        "activity": "updated",
        "table": "Sensors",
        "targetId": 23,
        "oldValues": {
            "name": "Luna Street Sensor"

    }

```

## Log Generation

The following models currently generate audit logs for any application-level `create`, `update`, and `delete` actions:

1. EmergencyContact
2. EvacArea
3. GovOp
4. IndivAcc
5. Location
6. Name
7. PhoneNumber
8. Sensor
9. SMSTemplate
10. User

>Since deactivation (soft delete) logic falls under PATCH, its associated logs are currently generated as `updated` event audit logs. A custom `deactivated` event can be implemented in the near future. 

Models can generate audit logs by simply implementing the `Auditable` trait and using the `CustomAuditable` implementation in the class definition. 

```php
use \OwenIt\Auditing\Contracts\Auditable;   // import the Auditable contract from the package

// implement the Auditable trait
class Sensor extends Model implements Auditable   
{
    use \App\Services\Audit\CustomAuditable;   // use the CustomAuditable implementation

    // define your class
}
```
